# Mod Manager, command line and Vortex

## Mod Manager (Tools > Mod Manager)

Every game / platform has its own mod library: `games\<game>\<platform>\mod_library`.

- **Install** a mod with *Install Archive…* (.zip / .7z / .rar), *Install Folder…*, or by dropping archives and
  folders onto the page. Blobset Tools finds the mod's root folder itself (the folder whose files match the game's
  file mapping), so wrapper folders inside archives don't matter. Installing a mod with the same name again updates it
  in place.
- **Load order**: mods lower in the list win when two of them have the same file. The green `+N` badge counts the
  files a mod takes over, the red `−N` badge the files it loses to a mod below it. The *Conflicts* tab lists them.
- **Enable / disable** with the check box. Disabled mods stay installed.
- **Build** (the same as the *Modify* button) puts the workspace `mods` folder and every enabled mod into the game.
  Mods you disabled or removed since the last build are taken out again (V3 / V4 games restore the original files
  first; V1 / V2 games always rebuild from the original header; the Mod Loader folder is always rebuilt). With
  nothing enabled, Build restores the original game files.
- Two built in entries take part in the load order: **Workspace** (`games\<game>\<platform>\mods`, what Modify always
  used) and **Vortex / external mods** (`<game>\BlobsetToolsMods`, shown when that folder exists).

### blobsetmod.json (optional, for mod authors)

Put it in the mod's root folder to give the mod a name and details:

```json
{
  "name": "Better Bats",
  "author": "Someone",
  "version": "1.2",
  "description": "HD bat textures.",
  "url": "https://www.nexusmods.com/..."
}
```

Without it the archive / folder name is used.

## Command line

`Blobset-Tools.exe --help` lists everything. Examples:

```
Blobset-Tools.exe --list-games
Blobset-Tools.exe --game "Cricket 24" --build
Blobset-Tools.exe --game "Cricket 24" --install "C:\Downloads\Better Bats.zip" --build
Blobset-Tools.exe --game "Cricket 24" --disable "Better Bats" --list-mods
Blobset-Tools.exe --game "Rugby League Live 3" --restore
```

- `--platform pc|ps3|xbox360` (default pc), `--game-location <blobset or folder>`, `--mod-loader on|off`, `--quiet`.
- Exit codes: 0 done, 1 a task failed, 2 bad arguments, 3 Blobset Tools is open / another command is running.
- Blobset Tools is a Windows program without a console of its own: in **cmd** use `start /wait Blobset-Tools.exe ...`
  and in **PowerShell** `Start-Process -Wait .\Blobset-Tools.exe -ArgumentList ...` to wait for it. Everything it
  prints is also written to `cli.log` in the data folder (`Documents\Blobset Tools`).
- Commands that change the game refuse to run while the Blobset Tools window is open (exit code 3).

## Vortex

1. In Blobset Tools: *Mod Manager > Set Up Vortex* (or run `Blobset-Tools.exe --install-vortex-extensions`). This copies
   the extensions of the games picked in setup (`vortex` folder next to the exe) into `%APPDATA%\Vortex\plugins` and tells them where
   Blobset Tools is.
2. Restart Vortex, then manage the game (Games > search for it). Steam games are found automatically; for AFL Live
   (not on Steam) set the game folder by hand.
3. Install mods in Vortex as usual. Vortex deploys them into `<game>\BlobsetToolsMods`; after every deploy / purge the
   extension runs `Blobset-Tools.exe --build`, which puts the mods into the game (or, after a purge, restores the
   original files).

Close the Blobset Tools window before deploying in Vortex (the build refuses while it's open; Vortex says so).

Vortex mods are combined with the Mod Manager's own mods: in the load order they are the *Vortex / external mods*
entry (highest priority by default).

The extensions are generated by `tools/make_vortex_extensions.py` (one per PC title; edit the template there).
